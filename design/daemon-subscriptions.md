# Paseo Daemon 按需订阅方案

已批准实施。改动范围为 `paseo-dsh-superagent` 的客户端和 daemon 端插件。DSH 继续保存业务数据，daemon 只在内存中保留有人订阅的最新视图。

## 迁移前的更新方式

| 功能 | 当前做法 |
| --- | --- |
| 侧栏「执行中」「待处理」 | daemon 共用一个读取器，每 15 秒读取概览。计数变化时推送，最后一人离开时停止。 |
| 主会话 | 每个打开的客户端每 3.5 秒请求最近的会话记录、卡片、模型和统计。向上翻页另行读取。 |
| 面板 | 当前概览、来源、触发、评估、执行、搜索和详情每 10 秒从客户端刷新。设置没有定时刷新。 |

## 一条订阅的生命周期

1. 客户端进入页面时通过 Paseo 建立订阅。daemon 先登记监听者，再发送首份快照。首次读取尚在进行时，新加入的客户端共用它；已有快照时可直接发送。
2. 相同实例、资源和规范化参数共用一个读取器。例如，同一台主机上两个客户端都看「执行／进行中」时共享读取；「执行／已结束」使用自己的筛选条件。每个读取器至多有一个进行中的请求，完成后才安排下一次。
3. daemon 比较客户端实际展示的字段，变化才推送。侧栏计数从概览的同一份结果派生，只向侧栏发送两个数。共享时采用当前订阅需要的最短间隔。常规页面按快照推送，会话按下述规则处理。
4. 离开页面、切换筛选、进入系统后台或断线时释放对应订阅。最后一个订阅释放后立即取消定时器，把取消信号传到 DSH 请求，并清理快照。移动端从面板进入主会话时显式释放原页订阅，即使原页组件还挂载着。侧栏只按宿主可观测的挂载和前后台状态订阅；抽屉收起是否卸载须在真机验证。
5. 重新连接或 daemon 重启后，订阅从新快照开始。Paseo 提供连接和取消信号，共享读数和首份快照由插件负责。普通连接恢复交给宿主；若单条订阅异常结束且宿主仍在线，支持显式重新订阅，避免界面一直停在旧数据。[Paseo 订阅说明](https://paseo.sh/docs/plugins/reference#subscriptions)

## 哪些数据实时更新

| 数据 | 建议行为 |
| --- | --- |
| 概览及侧栏 | 只有侧栏订阅时 15 秒一次，有概览页订阅时 10 秒一次。即使两处都打开，每轮也只读取一次上游概览。 |
| 来源、触发、评估、执行、当前线程和工单详情 | 只订阅正在看的视图，10 秒一次。筛选条件、线程或工单 ID 属于订阅参数。 |
| 列表翻页与搜索 | 实时更新列表首页或已提交的搜索结果。加载更多、定位某条历史触发按需读取。DSH 列表使用 offset；首页成员或顺序改变时使旧分页边界失效，保留阅读位置并提示更新，用户再加载时从新边界读取。较早的列表页是读取时的快照，打开具体工单后可看实时详情。 |
| Superagent 设置 | 只在设置子页打开时订阅已保存的配置，建议每 30 秒核对一次，以发现从 DSH Web 写入的修改。通过插件保存则立即通知相关视图刷新。远端版本变化时保留本地未提交的草稿，提示冲突。 |
| Paseo 插件连接设置 | 首次订阅返回地址、连接状态等可展示字段；本机保存配置时直接通知已打开的客户端。令牌和登录凭据留在主机。验证连接仍是一次明确操作。 |
| 主会话 | 有人查看时按现有 3.5 秒节奏读取实时尾页，两台设备共用一次。没有会话订阅时停止，侧栏订阅不会启动聊天读取。 |
| 图片、附件、工具详情、模型候选、提示词预览和版本历史 | 保留一次性 RPC。图片接近可视区才取内容，模型候选打开选择器时读取。会话中当前选用的模型跟随会话订阅更新。 |

## 主会话怎样少传数据

- 首次打开或重连发送近期会话窗口和当前状态。daemon 沿用已有的 DSH 会话投影与分页，首屏和历史页共用同一个记录转换函数。图片只带引用。
- daemon 每轮先读 DSH 会话投影。若实例、事件序号 `asOfSeq` 及构建消息所依赖的投影字段均未变，复用上次尾页并单独比较模型、卡片和统计；有新记录或投影依赖变化时，沿用已有逻辑从完整尾窗及前置上下文重算。增量只用于 daemon 给客户端传输已算好的显示结果。
- 正常追加时只传新增的可展示事件及有变化的会话状态。用户消息、执行步骤和工具结果按 DSH 事件序号去重。即使没有新增消息，也单独比较模型、忙闲、卡片和统计。
- 优先实现两种消息形态：近期窗口快照、追加更新。比较相邻两次窗口的重叠部分；旧记录内容改变、窗口断档或客户端发现更新基线不匹配时，重发近期快照。按订阅顺序应用，有连续边界时保留已加载的更早消息；断档时显示可往上补读的边界。移动窗口自然滑出的一条记录仍可留在客户端的已读历史中。
- 向上翻页继续使用 `beforeSeq`，只请求那一页。即使翻页返回得更晚，它也只能补充更早的行，不能把最新模型、卡片、状态或最近消息覆盖回旧版本。发送时先在本地显示气泡，收到正式消息后按原请求号合并。

## 写入、切换与故障

- 发送、选模型、重试、停止、改配置等仍是命令 RPC。命令完成后由 daemon 按面板、会话两个范围唤醒活跃读取器，并从 DSH 取回结果；影响两者的操作可同时唤醒。手动刷新也走这条路径。刷新碰上旧读取尚未完成时，将旧结果作废并合并成一次补读。读操作可重试，重连不会重新发送写命令。
- 配置切换或发现 Router 身份变化时，使旧订阅失效，清理旧快照及历史翻页结果，按新实例重新订阅。所有在途回调都校验实例和本轮订阅身份，写入继续校验目标实例。相同工单号不能跨实例复用。
- 暂时连不上 DSH 时把页面标记为数据可能已过期，侧栏隐藏无法确认的计数。相同故障只通知一次，有订阅时统一退避重试。遇到 401 提示更新凭据，验证并保存后立即恢复读取。

## 验收

1. 用上游请求计数证明两台设备看同一会话或筛选时只有一份轮询；只开侧栏时没有会话及其他页请求，全退出后没有任何插件定时上游请求。
2. 用下游事件计数和字节数验证，稳定页面在首份快照后无重复业务推送；普通新消息不重传尾页或图片。分别测量 daemon 到 DSH 和手机到 Paseo 两段流量。
3. 桌面发消息、换模型、停止工单或改配置，手机能从对应订阅看到结果。手机已有的输入草稿、历史阅读位置和乐观气泡保留。
4. 模拟断网重连、DSH 短暂出错、切换实例、历史页晚到、只更新卡片，以及列表插入导致 offset 移动。确认没有重复记录、静默缺页、旧数据倒灌或重复派单。

## 本机验证记录

- 两个独立 Paseo Web 客户端分别使用桌面及手机宽度，连接同一台 daemon。隔离测试实例记录到，两端打开同一执行列表只产生一次首页读取。暂停执行器后另一端收到更新，首页插入新工单时已翻页的一端保留阅读内容并能切换到最新列表。
- 两端同时查看主会话时，一条测试消息只投递一次，两端均收到。随后在 3.8 秒静止窗口内，上游读取会话投影一次，历史页读取零次。两个页面都触发后台可见性事件后，连续 15.5 秒内上游请求零次，恢复前台时重新读取近期窗口。
- 正式插件已用本机配置做只读桌面及紧凑布局检查，切换页面与模拟前后台能观察到 Paseo 的订阅和释放请求。iOS 真机锁屏、强杀和断网检测延迟仍待实机测量。

## Neon xhigh 代码复核与故障恢复验证

- 以 `d28bd73` 为基线，通过 Paseo 使用 Antigravity Neon xhigh 分别审查 daemon 与客户端。修复后，对同一资源逐订阅者投递，慢端合并中间更新，失败端独立退出；写入后加入的客户端等待有效首帧。切换连接重置退避，丢失命令回执仍会唤醒读取器。
- 客户端只对失效的连接重新订阅。持续有效的连接遇到 DSH 错误时由 daemon 重读。过期的回调和定时器无法干扰下一次订阅。历史翻页独立于实时消息的序号；连续快照保留有效在途页，断档或切实例时丢弃旧页。
- 两个独立 Paseo Web 客户端连接隔离测试实例。实测在「执行 → 概览 → 执行」之间延迟旧分页响应，列表仍能翻页。另一次分页返回 HTTP 503，点击重新读取成功取回原页。分别验证了首页变动以及已加载清单保留期间的暂停状态更新。
- 主动关闭一个测试客户端的真实 WebSocket，另一个客户端发送一条消息。前者自动重新订阅，在原会话收到这条消息一次，上游仅投递一次。基于 Web 的这项验证没有测量手机操作系统的锁屏或断网检测延迟。
